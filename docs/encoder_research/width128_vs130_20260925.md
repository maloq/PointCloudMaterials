# MACE width 128 versus 130 runtime comparison

Width 130 takes 50.4% longer per warmed update on the tested RTX
PRO 6000 Blackwell, with only 2.75% more encoder parameters. Retain width 128
for compute efficiency. This is a runtime test, not a prediction-quality result.

| Internal width | Encoder parameters | Warm median update | Warm examples/s | Peak allocated VRAM | Fresh median update |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 128 | 634,496 | 26.08 ms | 9,814 | 8.28 GiB | 1.127 s |
| 130 | 651,944 | 39.22 ms | 6,527 | 8.36 GiB | 1.206 s |

## Protocol and limits

Batch/microbatch 256; exported state 128-dimensional at both widths. Identical
16 batches from the existing relaxed Al training cohort, source/importance
weights and row IDs. Only internal width changes. Two MACE interactions,
correlation 2, irreps through ell=2, cuEquivariance ir_mul fused convolution,
fullgraph/dynamic compilation, float32 and TF32 disabled.

Encoder inputs: centered relaxed coordinates, Al species and center indicator;
radius 8 Å, cutoff 5 Å, at most 80 atoms, no extra halo, history or velocities.
Predictor input: exported embedding only. No explicit time/temperature inputs.
Initialization is random; no checkpoint or AP-specific objective is used.

Timed updates include graph assembly, forward, importance-weighted hazard NLL,
backward, gradient clipping and AdamW. Visit all 16 batches once at each width,
then measure six blocks of 16 repeated updates per width with alternating width
order. Median block times are reported. Width 128 blocks span 26.02–26.17 ms;
width 130 blocks span 39.19–39.28 ms. Two Dynamo graphs, no graph breaks.

Fresh medians exclude batch 0 with initial compilation and use batches 1–15.
Fresh means are 1.062 s (128) and 1.127 s (130). Both retain substantial
first-use overhead: the 50.4% warmed difference is not a full-run speed claim.
The test does not isolate which operation or alignment constraint explains
the width effect. No H100/H200 result or prediction-quality advantage is implied.

VRAM is peak PyTorch allocated memory including the shared relaxed geometry
bank and both resident models/optimizers. It excludes allocator-reserved and
driver/kernel memory. Prior diagnostics retained two domain banks, so their
absolute memory values are not directly comparable. A process check found no
other GPU compute process during this test.

## Reproduction

Use conda `pointnet-torch214`, an allocated GPU and the repository working
directory. Set `TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1`, `OMP_NUM_THREADS=1`,
`OPENBLAS_NUM_THREADS=1`, `MKL_NUM_THREADS=1`,
`PYTORCH_ALLOC_CONF=expandable_segments:True`, and `PYTHONPATH` to the repository.
Run the saved `technical/width_probe.py` through the allocation. The receipt
includes package versions, source/script hashes, parameter counts, atom/edge
counts, first-visit and block timings. `technical/sampled-rows.npy` preserves
sampled row IDs. No scientific configurations or defaults were changed, and
this local diagnostic did not create a W&B run.
