# GPU Ni EAM/FS implementation, October 7

`src/simulation/eam_gpu` implements the unchanged pure-Ni
`Ni1_Mendelev_2012.eam.fs` in CUDA. The pinned author file and SHA-256 are under
`configs/simulation/potentials/ni_mendelev2012/`. This is a force engine and a
local numerical/performance assay, not a production precursor campaign.

The engine uses the same cubic tables as LAMMPS EAM/FS, without smoothing or
refitting. GPU spatial bins build a reused Verlet list. One warp per atom computes
embedding densities; a second pass computes forces, energies and virial trace.
Directed neighbors avoid force atomics. Analytic derivatives of the same spline
and embedding functions provide up to four simultaneous force-direction products.
No MEAM angular densities or three-body screening are evaluated. CUDA graphs
capture the force/derivative kernels and reductions; construction is excluded
from steady-state timings. No fast-math flag is used.

Default force arithmetic is float32, with float64 integration inputs/outputs and
float64 scalar energy/virial reductions. Float64 force arithmetic is available
for numerical references. No global Al/MEAM defaults or existing jobs are changed.

```python
import torch
from src.simulation.eam_gpu import FastNi, CapturedNVE

model = FastNi('configs/simulation/potentials/ni_mendelev2012/Ni1_Mendelev_2012.eam.fs',
               atoms, box=box_lengths, dtype=torch.float32)
energy, forces = model.force(q64)
forces, force_tangents = model.force_tangent(q64, directions64)
virial_trace = model.virial_trace(q64)

# q64: Angstrom; v64: Angstrom/ps; one periodic cell, shape (N,3).
integrator = CapturedNVE(model, q64, v64, dt_ps=0.001, block_steps=100)
q64, v64 = integrator.run(1000)
```

The box is orthorhombic; periodic lengths must each be at least
`3 * (cutoff + skin)` (19.8 Angstrom with the default skin).
Use `set_box()` for a changed box so the neighbor list is rebuilt.
Omit box for open replicas; flattened equal-size batches have shape `(B,3*N)`.
Directions append a 1..4 axis to the coordinate shape. Returned tensors own their
storage. The API exposes analytic force tangents, not arbitrary PyTorch autograd.
Neighbor overflow, overlapping coordinates, invalid input and density outside the
fitted table cause errors. Native restart/integration precision is unchanged.

`CapturedNVE` captures blocks of velocity-Verlet steps including float64 kicks
and drifts. GPU displacement checks run on **every step**, and the GPU rebuilds
neighbors when any atom reaches half the skin from the actual list-build
coordinates. Errors are sticky until the block returns and rejects the state.
The caller chooses a block length dividing the requested step count. This path
supports one fixed periodic cell; it has no thermostat or barostat. Do not mutate
an integrator's tensors or its model/box while it is running. Use the force API
for response integration or other ensembles.

Run the local assay using conda `pointnet-torch214` on an allocated GPU:

```bash
UCX_TLS=tcp,self python -m src.simulation.eam_gpu.benchmark \
  --config configs/simulation/ni_eam_gpu_20261007.json

python -m src.simulation.eam_gpu.benchmark \
  --config configs/simulation/ni_eam_gpu_20261007.json --stage export
```

The default output identifies this implementation assay. For a new measurement,
copy the recipe and select a new output directory; preserve the existing receipts.
Compilation needs the configured CUDA toolkit (`CUDA_HOME` and its `bin` in
`PATH`); the October 7 allocation uses CUDA 13.4 with PyTorch 2.14/cu130.

The LAMMPS reference includes perturbed crystals, a separately melted cell and
open geometry. Validation covers energies, forces, virial, force derivatives,
replica isolation, a short float64-state NVE trajectory and its tangent response.
Benchmarks include full force API, kernel-only graph replay, Python-loop MD and
GPU-resident MD with dynamic neighbor rebuilds. The FastAl comparison measures
force and two-direction tangent calls on the same GPU, with float64 inputs and
float32 force arithmetic, using each material's own distorted FCC geometry.
Compilation and graph capture are excluded from timings. No W&B training run is
created. [Metric definitions](../metrics/ni_eam_gpu.md).

Scope limits: Ni thermodynamic calibration, NPT equivalence, long-time diffusion,
melting point, rare-event sampling and a Ni-specific simulator-response feature
protocol remain separate scientific work. A correct force engine does not establish
that prestructured liquid predicts crystallization.

## Verified October 7 results

The complete assay passed on one NVIDIA A40 (node22, dedicated job 1026757,
driver 610.57.04). See the [recorded configuration and completion](../../output/ni_eam_gpu/implementation-20261007/technical/complete.json),
[frozen implementation](../../output/ni_eam_gpu/implementation-20261007/technical/implementation.json)
and [metric definitions](../../output/ni_eam_gpu/implementation-20261007/tables/METRICS.md).

Against native LAMMPS `eam/fs` on periodic FCC, distorted FCC, a 10 ps melted
reference cell and an open 256-atom configuration:

- Float64 force RMS error: at most **1.8e-15 eV/Angstrom**; energy error at most
  **5.6e-12 eV/atom**.
- Production float32 force RMS error: at most **7.2e-6 eV/Angstrom**; energy
  error at most **1.1e-7 eV/atom**, virial-trace error below **1e-6 eV/atom**.
- Analytic force derivatives: relative error below **8.4e-8** against central
  finite differences; mixed-force derivatives differ from float64 by at most
  **5.4e-6** relative norm. The 20-step propagated response differs by **1.6e-8**.
- The captured 1 ps NVE trajectory has maximum energy excursion
  **2.48e-5 eV/atom**, with 70 neighbor rebuilds. Final position RMS difference
  from the ordinary float64-state/float32-force path is **5.2e-5 Angstrom**.

These are numerical accuracy checks for the potential's implementation. The
reference melt is a short validation preparation, without a structural claim
about precursor populations.
